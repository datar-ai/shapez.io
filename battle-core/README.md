# battle-core：戰鬥核心（第 2 步雛形）

無畫面的即時戰鬥模擬核心，用 Rust 寫成。遊戲畫面（之後的 Unreal Engine 5.8）只負責顯示和輸入，所有規則、AI 和結果都在這裡算。設計依據見文件〈戰鬥核心技術設計〉。

## 規則

- **時間**：每秒 20 步。每 60 秒是一個「脈衝」，脈衝開始時雙方各拿到 3 點指令點，可以暫停下令。
- **戰鬥群**：玩家對戰鬥群下令，不對單艦下令。沒有明確指令時，戰鬥群會鎖定目前的目標，除非另一個敵方戰鬥群明顯更近（距離不到目前目標的三分之二）才換目標。
  - 指令有攻擊、側擊（左或右）、固守、推進、集火部位、換準則、投入預備隊、跳躍撤離、招牌技。
  - 投入預備隊花 2 點，撤離免費，其他指令各 1 點。
  - 準則有三種：砲列停在射程邊緣；鐵砧在中距離釘住敵人；鐵鎚高速貼近，偏好側擊。有航艦的戰鬥群一律停在 3,800 距離外。
- **高度層**：主力艦層和戰機層。主砲打不到戰機，戰機只會被機砲和敵方戰機擊落。
- **艦種與招牌技**：每艘艦用自己艦種的招牌技。招牌技買下後會等到敵人進入射程，才開始充能 3 秒（雙方都看得到），發動後冷卻 30 秒。所以可以在脈衝開始時先下令，讓戰鬥群在適當時機自己發動。

  | 艦種 | 特色 | 招牌技 |
  |---|---|---|
  | 戰艦、旗艦 | 慢、裝甲厚、長程動能主砲 | 主砲齊射：充能時主砲停火；下一發傷害 ×3、射程 ×1.3，之後壓力大增 |
  | 巡洋艦 | 前向光束、飛彈 | 魚雷齊射：每艘 2 枚重魚雷，慢但重，要 3 次機砲命中才攔得下 |
  | 驅逐艦 | 快、全向速射砲、機砲最多 | 加力衝刺：10 秒內速度加倍 |
  | 航艦 | 慢、輕武裝、3 波戰機（每波 2 個中隊） | 全機出擊：所有中隊立刻補滿，三波一起出擊 |

- **機砲**：每艘艦都裝同一種機砲座（射程 600），只差座數：驅逐艦 5、旗艦 4、戰艦 3、航艦 3、巡洋艦 2。每座各自射擊，先打來襲的飛彈和魚雷，再打戰機。
- **戰機中隊**：每隊 10 架。每艘航艦有 3 波，每波 2 個中隊（20 架），共 60 架。
  - 平常分批上：敵人接近時派出第一波；這一波還在外面打，下一波就在機庫待命；這一波回航後，下一波補上。
  - 用「全機出擊」招牌技，三波一起出。
  - 出擊後，中隊會找附近最有價值、驅逐艦和航艦護衛最少的敵方戰鬥群下手，在目標周圍約 350 距離盤旋攻擊。
  - 附近有敵方戰機時先纏鬥。
  - 剩 3 架以下回航艦補機。航艦沉了，停機中的中隊跟著損失，在外面的打到最後一架。
- **傷害**：
  - 光束對護盾 ×1.5。
  - 動能彈對護盾 ×0.75，但只吃一半裝甲。
  - 飛彈、魚雷會被機砲攔截；機砲打戰機的命中率只有打飛彈的 25%。
  - 護盾分前、左、後、右四面。受到側面或背面攻擊時，士氣掉得更快。
- **地形**（戰機飛在上面，不受阻擋）：
  - **小行星帶**是直射火力的牆：光束和主砲的射線穿過小行星帶就打不到，離邊緣 300 以內的艦船仍能對外開火、也會被打到。在裡面速度剩 60%、較難被打中，飛彈穿越時可能撞毀。
  - **星雲**：裡面的艦船只有 1,000 距離內的敵艦看得到、打得到，戰機完全找不到。光束傷害減半，護盾不會回充。
- **部位傷害**：引擎、武器、護盾產生器、艦橋各自可以被打壞，被集火的部位受傷機率較高。
- **士氣**：
  - 戰鬥群士氣歸零就潰散。
  - 旗艦被擊沉時，全軍士氣重挫。
  - 一方損失過半艦隊價值後，全軍開始動搖。
- **撤離**：下令後，戰鬥群 15 秒內無法開火，之後跳離戰場，艦船保留。
- **AI 指揮官**：依效用分數挑指令（包括何時用招牌技），用跟玩家一樣的指令點。招牌技可以跟同一戰鬥群的其他指令一起下。
  - 雙方都交給 AI，就是自動戰鬥結算（`run_auto`）。
  - 搶位置：每個脈衝，AI 先照規則排出指令，再試幾種改法，每種都在戰鬥的複本上往前模擬 20 秒，留下結果最好的。改法包括：某個戰鬥群移進最近的星雲、移到最近的小行星帶、繞到目標的左前或右前、原地固守。
  - 看地形選目標：砲列和鐵砧先打看得到的敵人，躲在星雲裡的敵人算三倍遠；鐵砧和鐵鎚會逼近到 900 以內，把星雲裡的敵人挖出來。這一項雙方戰鬥群都會做，玩家的也一樣。
  - 超過 1,500 艘的大戰只用規則排指令，不往前模擬。
- **戰報**：戰後列出勝負、雙方損失、受到最多的傷害類型、最佳戰鬥群。

## 示範戰與平衡

示範戰共 72 艘，雙方編成完全相同，每方 36 艘。戰鬥群名稱寫成「準則：艦種」：

- 砲列：旗艦 1、戰艦 3。
- 航艦：航艦 2、驅逐艦 4。
- 鐵砧：巡洋艦 6。
- 鐵鎚：驅逐艦 12。
- 預備：巡洋艦 4、驅逐艦 4。

兩邊布陣不同：

- **藍方散開**：鐵砧在左翼、鐵鎚在右翼，砲列居中，航艦在左後方，預備在右後方。
- **紅方厚中央**：砲列居中，鐵砧在它右前方，航艦在正後方；鐵鎚放在左翼，預備在右後方。

每場開戰時，各戰鬥群的位置依種子小幅偏移（橫向 300、縱向 400 以內）。不偏移的話，一個固定布陣幾乎決定每一場的走向，挪 40 距離勝率就能從 40% 跳到 80%。

地形是公平的：紅方半邊是藍方半邊繞中心轉 180 度。從各自的角度看，雙方都有：左邊遠處一片星雲、右前方近處一片小星雲、中線左側一塊小行星、右翼遠處一片小行星帶。小行星會擋火力，所以中線兩塊把戰場隔成幾條通道。

用 `balance` 讓 AI 對打：

- **勝負**：400 場，藍 197 勝、紅 194 勝、平手 9。
- **長度**：大多 2–4 個脈衝，平均 3.5；少數兩邊都躲著不打，拖到 10 個脈衝的上限變成平手。
- **速度**：每場約 1 秒（AI 往前模擬佔大部分）。

## 地形與 AI

用 `balance --no-terrain blue`（`red`、`both`）關掉一方或雙方的地形判讀，就能量出它值多少。每組 400 場：

| 對局 | 藍方勝率 | 紅方勝率 |
|---|---|---|
| 雙方都不看地形 | 34% | 66% |
| 只有藍方看 | 58% | 41% |
| 只有紅方看 | 26% | 73% |
| 雙方都看 | 49% | 49% |

看地形的一方，勝率提高 7 到 24 個百分點。示範戰的布陣是在雙方都看地形的情況下調平的。

一路走來的教訓：

- **舊規則下地形不值得搶**：小行星帶只讓敵人命中率降 20%，也擋不住戰機；戰艦每秒只走 30，挪 1,000 距離就要半分鐘。
- **固定分數的搶位置會吃虧**：先試過「掩護加幾分、每走一秒扣幾分」這種寫死的評分，在新規則下還是讓使用的一方少贏 3 到 4 個百分點。原因是它看不出移動會不會打亂整體陣形、會不會把側面露給別的敵人。
- **往前模擬才有用**：直接在複本上試跑 20 秒，好不好由結果決定，勝率才明顯上升。

## 確定性

同一個種子一定得到同一場戰鬥，不管用幾個執行緒、在哪個平台跑。原生版、C 介面和瀏覽器（WebAssembly）版跑同一個種子，最後的狀態雜湊完全相同。做法如下：

- 全部用整數定點數。三角函數和反正切用查表，表本身只用 IEEE 保證的運算建出來。
- 亂數是無狀態雜湊，由（種子、步數、艦船、用途）決定，跟執行順序無關。
- 每步分階段：
  1. 各艦平行思考，只讀快照。
  2. 依固定順序套用結果。
  3. 戰機中隊依編號順序更新。

## 執行

需要 Rust 1.84 以上。

```sh
cargo test --release                            # 16 項測試
cargo run --release --bin battle -- --seed 1    # 跑示範戰，印出每個脈衝的指令和戰報
cargo run --release --bin battle -- --seed 1 --replay out/r1.json
cargo run --release --bin balance -- --seeds 1000
cargo run --release --bin bench                 # 5,400 艘的效能測試
```

## 試玩畫面

```sh
rustup target add wasm32-unknown-unknown        # 只需一次
python3 viewer/build.py out/battle.html         # 可以下令的試玩頁（核心編成 WebAssembly 放進網頁）
python3 viewer/build.py out/replay.html out/r1.json   # 包進一場重播
```

直接打開 `viewer/index.html` 也可以，但只能載入重播檔。

**試玩頁：你指揮藍方，紅方由 AI 指揮。**

1. 每個脈衝暫停時，點選藍方戰鬥群（右側清單或地圖）。
2. 下令：
   - 攻擊或側擊：再點一個紅方戰鬥群。
   - 推進：再點地圖上的目的地。
   - 撤離：要按兩次確認。
3. 按「開打 60 秒」（或空白鍵）繼續。

打完會顯示戰報。可以換種子重新開戰，或勾選「藍方也交給 AI」觀看 AI 對打。

**畫面內容：**

- 各艦依艦種和陣營上色。
- 戰機中隊以小點群表示，攻擊時繞著目標盤旋。
- 光束和動能命中線；主砲齊射畫成粗線。
- 戰機攻擊虛線、點防禦擊落戰機的細黃線、飛彈、魚雷、擊沉閃光。
- 招牌技充能圈、戰鬥群目標箭頭、士氣條。
- 地形。

## 效能

在 4 核心的雲端機器上測試，5,400 艘艦船（含 300 艘航艦、1,800 個戰機中隊）、1,200 步：

| 執行緒 | 平均每步 | 最慢一步 | 每秒步數 |
|---|---|---|---|
| 1 | 6.5 ms | 9.8 ms | 153 |
| 2 | 3.9 ms | 6.1 ms | 254 |
| 4 | 2.3 ms | 3.8 ms | 426 |

目標是每步 1–2 ms。還沒做的優化：

- 常駐執行緒池（目前每步重開執行緒，最慢一步的尖峰主要來自這裡）。
- 降低目標搜尋頻率。

示範戰每步約 0.04 ms。

## 接 Unreal Engine 5.8

核心編成 `battlecore.dll`（Windows）或 `libbattlecore.so`/`.a`，C 介面宣告在 `include/battlecore.h`。

- **記憶體**：核心擁有所有記憶體。遊戲端透過 `bc_ships` 讀艦船陣列，透過 `bc_events` 讀本步事件；另有 `bc_header_json` 和 `bc_frame_json` 可以取得 JSON 格式的完整狀態（含戰機、飛彈、地形）。
- **錯誤處理**：Rust 的 panic 不會穿過邊界，會轉成錯誤碼。
- **UE 端做法**：
  - 包成 ThirdParty 模組，載入 DLL。
  - 每個 tick 呼叫 `bc_step`，把位置和朝向寫進 Instanced Static Mesh。
  - 事件轉成 Niagara 特效：開火、命中、擊沉、護盾過載、招牌技、戰機攻擊。
- **範例**：`examples/ffi_smoke.c` 是最小的 C 範例，結果跟 Rust 命令列版相同。

```sh
cargo build --release
cc examples/ffi_smoke.c -Iinclude target/release/libbattlecore.a -lpthread -ldl -lm -o ffi_smoke && ./ffi_smoke
```

## 檔案

| 路徑 | 內容 |
|---|---|
| `src/fixed.rs` | 定點數、查表三角函數、雜湊亂數 |
| `src/types.rs` | 艦種數值、武器、招牌技、戰機、指令、事件 |
| `src/terrain.rs` | 地形格網與效果 |
| `src/grid.rs` | 均勻格網（每步用計數排序重建） |
| `src/battle.rs` | 模擬主體：移動、索敵、開火、飛彈與魚雷、點防禦、戰機、招牌技、傷害、士氣、勝負 |
| `src/ai.rs` | AI 指揮官 |
| `src/scenario.rs` | 示範戰配置 |
| `src/replay.rs` | 重播紀錄、JSON 輸出、戰報 |
| `src/ffi.rs` | C 介面（也是瀏覽器版的介面） |
| `src/bin/` | `battle` 命令列、`balance` 平衡測試、`bench` 效能測試 |
| `tests/` | 確定性與規則測試 |
| `viewer/` | 試玩與重播畫面、打包腳本 |

## 下一步候選

- AI 往前模擬的更多改法：誘敵進小行星帶的射界、兩個戰鬥群一起移動。
- 常駐執行緒池，把大規模戰鬥壓到每步 2 ms 以下。
- 第三個高度層：軌道與大型地形。
- 更多地形種類：重力井、戰場殘骸。
- 開始接 Unreal Engine：先做一個能顯示這場示範戰的 UE 專案。
