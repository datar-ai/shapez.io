# battle-core：戰鬥核心（第 1 步雛形）

無畫面的即時戰鬥模擬核心，用 Rust 寫成。遊戲畫面（之後的 Unreal Engine 5.8）只負責顯示和輸入，所有規則、AI 和結果都在這裡算。設計依據見文件〈戰鬥核心技術設計〉。

## 這一步做了什麼

- **模擬平面**：2D 平面加高度層的設計，這一步先只做主力艦層。
- **時間**：每秒 20 步。每 15 秒是一個「脈衝」，脈衝開始時雙方各拿到 3 點指令點，可以暫停下令。
- **戰鬥群**：玩家對戰鬥群下令，不對單艦下令。
  - 指令有攻擊、側擊（左或右）、固守、推進、集火部位、換準則、投入預備隊、跳躍撤離。
  - 投入預備隊花 2 點，撤離免費，其他指令各 1 點。
  - 準則有三種：砲列停在射程邊緣；鐵砧在中距離釘住敵人；鐵鎚高速貼近，偏好側擊。
- **艦種**：戰艦、巡洋艦、驅逐艦、旗艦，各有不同速度、轉向、射界和武器。
- **傷害**：
  - 光束對護盾 ×1.5。
  - 動能彈對護盾 ×0.75，但只吃一半裝甲。
  - 飛彈會被驅逐艦的點防禦攔截。
  - 護盾分前、左、後、右四面。受到側面或背面攻擊時，士氣掉得更快。
- **部位傷害**：引擎、武器、護盾產生器、艦橋各自可以被打壞，被集火的部位受傷機率較高。
- **士氣**：
  - 戰鬥群士氣歸零就潰散。
  - 旗艦被擊沉時，全軍士氣重挫。
  - 一方損失過半艦隊價值後，全軍開始動搖。
- **撤離**：下令後，戰鬥群在一個脈衝內無法開火，之後跳離戰場，艦船保留。
- **AI 指揮官**：依效用分數挑指令，用跟玩家一樣的指令點。
  - 雙方都交給 AI，就是自動戰鬥結算（`run_auto`）。
- **戰報**：戰後列出勝負、雙方損失、受到最多的傷害類型、最佳戰鬥群。

## 確定性

同一個種子一定得到同一場戰鬥，不管用幾個執行緒。這是重播、存檔和日後連線對戰的基礎。做法如下：

- 全部用整數定點數。三角函數和反正切用查表，表本身只用 IEEE 保證的運算建出來，所以各平台結果一致。
- 亂數是無狀態雜湊，由（種子、步數、艦船、用途）決定，跟執行順序無關。
- 每步分兩階段：
  1. 各艦平行思考，只讀快照。
  2. 依固定順序套用結果。

測試 `tests/determinism.rs` 會驗證同種子同結果，也會驗證 1、2、4 個執行緒的結果相同。

## 執行

需要 Rust 1.84 以上。

```sh
cargo test --release                            # 7 項測試
cargo run --release --bin battle -- --seed 1    # 跑示範戰（68 艘），印出每個脈衝的指令和戰報
cargo run --release --bin battle -- --seed 1 --replay out/r1.json
cargo run --release --bin bench                 # 5,100 艘的效能測試
```

## 2D 除錯重播畫面

`viewer/index.html` 直接用瀏覽器打開，按右上角載入 `--replay` 產生的 JSON 即可。

- **播放控制**：
  - 播放、暫停、單幀前後。
  - 1–8 倍速。
  - 可選在每個脈衝自動暫停。
  - 時間軸可以拖曳。
- **畫面內容**：
  - 各艦依艦種和陣營上色。
  - 光束和動能命中線、飛彈、擊沉閃光、護盾過載圈。
  - 戰鬥群目標箭頭和士氣條。
- **右側面板**：指令紀錄（點一下可以跳到那一刻）和戰報。

要把重播直接包進網頁、打開就能看：

```sh
python3 viewer/embed.py out/r1.json out/r1.html
```

## 效能

在 4 核心的雲端機器上測試，5,100 艘艦船、1,200 步，最多同時有 1,432 枚飛彈：

| 執行緒 | 平均每步 | 最慢一步 | 每秒步數 |
|---|---|---|---|
| 1 | 7.4 ms | 10.7 ms | 136 |
| 2 | 4.4 ms | 14.2 ms | 228 |
| 4 | 2.6 ms | 5.4 ms | 383 |

目標是每步 1–2 ms（每秒 20 步的預算是 50 ms，模擬只能佔一小部分）。還沒做的優化：

- 常駐執行緒池（目前每步重開執行緒，最慢一步的尖峰主要來自這裡）。
- 降低目標搜尋頻率。
- 內迴圈少做開根號。

示範戰（68 艘）每步約 0.04 ms，種子 1–6 都在 7–8 個脈衝（104–120 秒）內分出勝負。示範配置不對稱，目前紅方全勝；平衡是第 2 步的工作。

## 接 Unreal Engine 5.8

核心編成 `battlecore.dll`（Windows）或 `libbattlecore.so`/`.a`，C 介面宣告在 `include/battlecore.h`。

- **記憶體**：核心擁有所有記憶體。遊戲端透過 `bc_ships` 讀艦船陣列（結構陣列），透過 `bc_events` 讀本步事件。指標在下一個會改變戰鬥的呼叫前有效。
- **錯誤處理**：Rust 的 panic 不會穿過邊界，會轉成錯誤碼 `BC_ERR_PANIC`。
- **UE 端做法**：
  - 包成 ThirdParty 模組，載入 DLL。
  - 每個 tick 呼叫 `bc_step`，把位置和朝向寫進 Instanced Static Mesh。
  - 事件轉成 Niagara 特效：開火、命中、擊沉、護盾過載。
- **範例**：`examples/ffi_smoke.c` 是最小的 C 範例，跑完整場戰鬥，狀態雜湊跟 Rust 命令列版相同。

```sh
cargo build --release
cc examples/ffi_smoke.c -Iinclude target/release/libbattlecore.a -lpthread -ldl -lm -o ffi_smoke && ./ffi_smoke
```

## 檔案

| 路徑 | 內容 |
|---|---|
| `src/fixed.rs` | 定點數、查表三角函數、雜湊亂數 |
| `src/types.rs` | 艦種數值、武器、傷害類型、指令、事件 |
| `src/grid.rs` | 均勻格網（每步用計數排序重建） |
| `src/battle.rs` | 模擬主體：移動、索敵、開火、飛彈、點防禦、傷害、士氣、勝負 |
| `src/ai.rs` | AI 指揮官 |
| `src/scenario.rs` | 示範戰配置 |
| `src/replay.rs` | 重播紀錄、戰報 |
| `src/ffi.rs` | C 介面 |
| `tests/` | 確定性與規則測試 |
| `viewer/` | 2D 除錯重播畫面 |
